# Випуск 1: спроба випуску v62 і точне повернення

[Поточний стан](../ПОТОЧНИЙ-СТАН.md) | [VR-010](../звіти-перевірки/звіти/ЗП-010/ОГЛЯД.md) | [Нідерландською](../../nl/rapporten/VERSIE-001-V62-UITGAVEPOGING-EN-TERUGDRAAIING-2026-07-22.md)

- **Дата:** 2026-07-22
- **Вихідний запит:** `REQ-0033`
- **Загальний стан:** `BLOCKED`
- **Робоче середовище після закриття:** незмінна версія v57
- **Історичний кандидат:** незмінна версія v62
- **Розгортання в передпусковому середовищі:** 0

## Втілений кандидат

Сукупна версія v62 містила клієнтські доробки першочергового рівня P0 Випуску 1, динамічний контекст активного та спільного облікових записів, узгоджений інтерфейс міток Gmail, відновлення після застарілого маршруту, обмежений кеш у межах облікового запису, контрольні точки відновлення чернеток, чутливу до версії активацію клієнта та точну ізоляцію запитів списку листів за кожним обліковим записом. PR #29 і PR #30 злито у звичайному режимі; GitHub і приватне дзеркало GitLab досягли фіксації `42dfbd76d1e904fe065094010f61418da8896978`.

## Перевірені докази

- Набір тестів продукту й випуску: `494/494`; набір тестів перехідного мосту: `3/3`; обов'язкові перевірки GitHub пройдено.
- Незмінну версію v62 та контрольні суми її вихідного коду зчитано назад без розбіжностей; під час приймання існувало лише одне захищене передпускове розгортання.
- Передпускове середовище лише для власника завантажило поштову скриньку, фото профілю, три ізольовані кореневі скриньки Gmail і спільне представлення; перемикання на контрольований додатковий обліковий запис і назад не потребувало OAuth. Видимий список залишався обмеженим запитаним обліковим записом.
- Два свіжі запуски робочої версії v62 завантажили поштову скриньку після просування.
- Один дозволений контрольний лист власника самому собі не створив картки в Telegram через правило виключення `SENT`; два запуски `/check` не створили дубля. Це доводить межу придушення та уникнення дублювання, але не доводить зовнішню автоматичну доставку `INBOX`.
- Вивід точного повернення повідомив про перехід v62 -> v57. Попередня перевірка після повернення: стабільна v57, головна версія `stable_v57`, незмінна v62 готова, передпускових розгортань 0, журнал `rolled_back`.
- Два свіжі запуски робочої версії v57 завантажили поштову скриньку без мережевої помилки.

## Заблоковані докази

Обов'язковий слід виконання Apps Script після розгортання v62 отримати не вдалося. Офіційна кінцева точка процесів повернула помилку 403, а команда `clasp logs` зупинилася через відсутність налаштованого ідентифікатора проєкту GCP. Перенесення керованого Apps Script типового проєкту лише заради читання журналів було відхилено, оскільки це могло скасувати чинні дозволи авторизації. Нова процедура згоди OAuth не запускалася.

Тому проблема GT-030 залишається відкритою: версія v62 зберегла той самий код фонового виконавця, що й гілка кандидата, де раніше було зафіксовано виконання тривалістю 214,96 секунди та накладання вікна виконання. Тотожність вихідного коду має стан `ПЕРЕВІРЕНО`; окрему регресію часу виконання, властиву саме v62, не доведено. Без очищеного від вмісту пофазового сліду вікон виконання пропускний бар'єр випуску щодо 150 секунд без накладань залишається у стані `НЕ_ПЕРЕВІРЕНО`.

## Безпечний кінцевий стан

Робоче середовище перебуває на точній незмінній версії v57, передпускових розгортань 0, меню Telegram веде на робоче середовище, а незмінну версію v62 збережено для історичного порівняння. Версію v62 не можна змінювати або повторно просувати. Майбутня незмінна версія потребує усунення першопричини GT-030 і нових доказів виконання; звичайні поштові зміни не виправдовують перемикання випусків туди-сюди.

Під час закриття не було змінено жодного стороннього листа, мітки Gmail, чернетки, запису OAuth, маркера доступу, таємної властивості або зіставлення поштових зон облікових записів.
